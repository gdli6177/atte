# 工作区兼容检查与 v5 迁移

状态：0.14.0 当前实现。

## 目标

升级应用或打开旧目录时，Atte 必须优先保留原始数据。有效旧快照先备份校验再迁移；
无效、未知或损坏快照停止加载并保留原文件，不自动覆盖，也不创建一份空工作区冒充
迁移成功。

详细操作与回滚见[升级说明](../upgrade-atte.md)。

## 当前状态版本

`WorkspaceState.version = 5`。v5 包含：

- 项目与上线策略；
- 事项、消息、活动、附件、等待、提醒、交付与决定；
- 唯一管家、Herdr 现场与 Agent runtime；
- 看门狗间隔；
- 退役能力的 `history` 摘要。

自主 scheduler、continuation、独立复核、Bot、本地能力包、后端选择和工人偏好不是
可重新启用的 v5 配置。

## 有效旧快照

| 原版本 | 备份 | 行为 |
| --- | --- | --- |
| v2 | `.atte/state.v2.backup.json` | 校验后迁移到 v5 |
| v3 | `.atte/state.v3.backup.json` | 校验后迁移到 v5 |
| v4 | `.atte/state.v4.backup.json` | 校验后迁移到 v5 |

迁移顺序：

1. 在工作区锁内读取原 `state.json`。
2. 校验旧结构。
3. 备份原始字节到对应 `state.vN.backup.json`。
4. 拒绝符号链接、目录和与原始字节不一致的既有备份。
5. 校验备份 SHA-256，原子发布后再次校验。
6. 在内存中完成 v5 退役与迁移。
7. 原子替换 `state.json`。

任何一步失败都停止并保留原 `state.json`。有效 v5 再次读取时不重复迁移或创建备份。

## 迁移映射

- 事项、消息、活动、附件、决定和已有交付保留；
- 旧交付进入人工验收注意力；
- 未完的自主、续跑、复核、探索或发布实验事项进入迁移确认，暂停执行；
- 旧 Orca 事项保留原状态和现场引用，标记只读历史；
- 旧自主设置、Bot、工人偏好与验收授权写入 `history`；
- 负责人命令留空时继承管家。

## 无效快照

以下情况保留原目录并阻塞加载：

- 只有 v1 或更低版本；
- 未来版本；
- 损坏 JSON；
- 缺字段或结构无效；
- 只有旧事件日志而没有有效快照。

Atte 不自动把 `.atte` 改名为 `.atte.backup-*`，也不删除附件或其他原文件。用户应先
保留目录、检查诊断并修复；不要用旧版直接打开已经升级的 v5 快照。

## 文件与隐私

迁移不跟随符号链接，不复制特殊文件，不修改图片字节。决定账本、附件和事件继续
留在同一工作区。Atte 不上传状态，也不从旧终端引用推断新的负责人现场。

## 验收

- `packages/core/test/workspace-v5.test.ts` 覆盖 v2/v3/v4 迁移、备份失败停止、
  幂等读取、旧交付人工验收、实验事项暂停与 Orca 只读。
- `packages/core/test/core.test.ts` 覆盖无效 JSON、未来版本、缺快照和事件日志不能
  被静默归档。
- `pnpm test` 验证桌面与 CLI 共用同一状态锁和迁移语义。
