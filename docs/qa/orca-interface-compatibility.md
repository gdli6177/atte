# Orca 接口兼容验收：0.13.2

日期：2026-11-15。用户要求使用本机 Orca 测试并解决设置无法选择的问题，随后明确指出固定版本名单难以支持持续升级。

## 根因与准入决定

Atte 0.13.1 的应用身份与 CLI 版本检查能够识别官方 Orca 1.4.259，但检测器只允许
1.4.258，因此返回 `unverified`。实际安装应用与打包 UI 的回归都复现了该阻塞。

0.13.2 改用以下事实决定可用性：

1. 官方 bundle ID、签名发布者与代码完整性正确，应用与内置 CLI 的版本一致。
2. `agent-context --json` 返回可识别的静态接口说明，并具备 Atte 调用的命令与参数。
   缺少具体命令或参数时，明确说明缺失项；额外命令与可选参数不导致拒绝。
3. 切换预检连接真实 runtime，核对进程、运行时代次、版本一致性与三项必要能力，
   成功后才能停止旧现场。该预检失败会保留原后端、epoch 与现场。

`TESTED_ORCA_VERSIONS` 仅记录曾真实验收的版本，不参与准入。推荐安装包的固定
URL、大小与 SHA-256 仍是独立的下载完整性约束，不要求用户安装版本与之相等。

## 本机 1.4.259 实测

- 应用：`/Applications/Orca.app`，应用和内置 CLI 均为 `1.4.259`。
- bundle ID：`com.stablyai.orca`；Team ID：`6CX3WHS9HZ`；严格签名检查通过。
- 使用独立的 `/private/tmp/atte-orca-259-pos2uo9a/orca-profile`，不复制或操作正常用户 profile。
- 真实契约覆盖中文目录、包含中文与空格的 argv、1,041 项 PATH、48,001 字节完整单次投递、
  相同请求不重复创建/发送、20 次定位以及身份绑定的确认关闭。
- 原生 Agent 会话恢复仍为 `unsupported`，继续按目标记录恢复，不把终端 API 可用等同于原生 resume。
- 新增 `pnpm test:orca-selection`，针对本机官方安装和真实打包 Atte 检查“可切换”、重新检测、
  深浅主题与切换确认按钮。该测试无 IPC 状态替身，在确认处取消以保留原后端选择；
  不声称已自动切换用户的真实工作区。

## 自动回归范围

- 合法接口下的 `1.4.258`、`1.4.259`、`1.4.260`、`2.0.0`、`9.0.0` 均不因产品版本被拒绝。
  其中未来版本仅是接口准入策略 fixture，不能当作真实安装过这些版本的证据。
- 缺少 `terminal send`、缺少 `--retry-request`、未知接口说明格式、签名失败、应用缺失均会拦截。
- 接口探测暂时失败允许重新检测；真实 runtime 缺少必要能力时，即使 CLI 说明完整也不能切换。
- 官方新版本与推荐下载包版本不同，不会使已兼容的安装重新变成未验证，也不会自动降级应用。

## 本机安装验收

已构建 0.13.2 的真实 DMG / ZIP，并完成类型检查、全量单元测试、真实 Orca 契约、
首启、桌面、深浅主题矩阵与安装器检查。首启状态模拟补充了后台异步刷新隔离，避免
真实安装状态覆盖测试的四态 fixture；真实 Orca 选择测试保持无 IPC 状态替身。

本机 `/Applications/Atte.app` 已替换为 0.13.2，旧应用先完整备份，重启后再次通过
该安装路径执行 `test:orca-selection`。实际安装的 Orca 1.4.259 显示“可切换”，可进入
切换确认。测试在确认处取消，正常用户的后端选择与工作区数据没有被切换测试改写。
