# Atte 0.13.1：用户界面反馈验收

日期：2026-11-15。发布授权来自用户在本次任务中要求「前面说的问题，都处理了然后发布新 release」。

## 范围与结论

| 反馈 | 处理 | 验证入口 |
| --- | --- | --- |
| 未选存储位置时切换左侧菜单没有对应正文，设置打不开 | 各页面可独立导航；待办与目标显示各自引导，设置可首次选目录；依赖工作区的写入先禁用 | `pnpm test:first-launch` |
| Orca 已安装却显示“先安装” | 四种检测状态分别展示，点击说明实际原因；刷新后两处显示一致；新版本保留明确的兼容说明与选择已有应用入口 | `pnpm test:first-launch` 中隔离的 IPC 状态 fixtures |
| “我的工作台”区块重复 | 移除侧栏区块和专用样式，使用“注意力”返回总览；现有导航测试同步 | `pnpm test:first-launch`、`pnpm test:desktop`、`pnpm test:onboarding` |
| 中文品牌副标题移除 | 界面、原生关于面板、CLI 帮助、包描述与当前品牌文档统一 `The attention layer` | CLI 测试、首启与桌面烟测 |
| 吉祥物不匹配产品主题 | 使用用户明确选定的装甲双耳小管家原图，统一接入首启、首页和管家卡片并平滑缩放 | 首启真实图片加载与 `pnpm test:atte-ui`；来源见[定稿](../brand/mascot.md) |

首启测试先在修复前的真实打包应用上运行，点击“待办池”后无法找到对应标题，
可访问性快照显示导航已切到待办池、正文仍是欢迎页，复现用户原始反馈。
同一测试在修复后的应用通过，并核对设置内首次选目录、取消选择保留页面、
未选目录时不创建工作区数据，以及目录选定后正常进入工作区。

## 兼容边界

Orca 安装信息与兼容验收是不同事实。UI 测试中的 `1.4.259` 是未验证状态 fixture，
用于回归原始误报，不构成该版本真实 Session 契约通过的证明。
本次保持 `1.4.258` 的已验证白名单与官方安装包，不自动降级或覆盖用户已有 Orca。

## 本地验证

- `pnpm typecheck`：Core、CLI、Session Adapter 与 Desktop。
- `pnpm test`：CLI 64、Core 168、Session Adapter 71、Desktop 193，共 496 项。
- `node scripts/design-contrast.mjs`：66 组对比度、21 个颜色和 8 档字阶。
- `pnpm desktop:dist`：真实 macOS arm64 应用及 DMG / ZIP，保持现有 ad-hoc 签名流程。
- `pnpm test:first-launch`：本次新增的首启、设置、品牌与 Orca 状态回归。
- `pnpm test:atte-ui`：深浅主题、900×700 / 1024×768 / 1440×960 的 30 张场景截图，以及焦点、溢出、正文对比度和单一主动作。
- `pnpm test:desktop`、`pnpm test:methods`、`pnpm test:task-pool`、`pnpm test:installers`、`pnpm test:terminal`：既有行为与安装产物回归。
