Atte 0.14.2 · macOS Apple Silicon

## 现场续做与验收反馈

- 整体范围从 A 延伸到 A2 时，Agent 在实质写回前读取最新目标，并显式维护覆盖整体工作的短标题。普通进度不反复改名，原始说明与用户原话保留；活动记录前后标题和实际操作者。
- 待验收时在负责人现场补充明确的新要求，负责人先保存现场回执；管家核对原话与当前编号，先更新必要的标题，再通过 `goal rework` 退回推进，确认 `active` 后交给原负责人继续。
- “给管家发消息”继续作为统一反馈入口，发送本身保留待验收。普通提问由负责人回答，明确修改要求由管家退回推进；“验收通过”仍由人明确操作，受管 Agent 不能代替验收。
- 修复负责人保存普通问答时的消息署名与重复派发：答案保留负责人身份和原现场回执，不再被误记成人的新反馈。
- 注意力卡增加“负责人最近回复”，显示 Hook 已观测到的有界文本，保留换行与安全转义。回复是现场信息，状态仍以结构化写回为准，不自动保存整段对话。
- 在待验收状态误用 `progress` 或 `update --status active` 时，错误信息给出当前目标的 `goal rework` 命令。旧 attention、旧现场回执、旧后端身份仍无法覆盖新一轮交付。

## 保留

Herdr 仍是唯一执行后端。看门狗、回执恢复、协调收件箱、人工验收、上线策略和高风险审批继续保留；OMP Hook revision 3 的 EPIPE 修复与 fail-open 行为继续生效。

## 升级

- 替换应用后，在“设置 → 高级与维护”重新安装 Atte CLI 并更新内置 Atte Skill。
- 新管家案卷与负责人通知会带上本版协议；正在执行的旧回合可能仍使用旧指令，必要时结束该回合，再由管家向原负责人转达最新要求。无需删除或重建事项。
- 工作区仍为 v5，不新增迁移，不追溯修改旧标题或状态。Hook 不自动判断返工、批准或验收；现场同步依赖 Agent 按协议显式写回。
- 已运行的 OMP 若仍持有 revision 3 之前的 extension，仍需重启相应 OMP 进程。

仅提供 macOS Apple Silicon（arm64）的 DMG、ZIP 和 `SHA256SUMS.txt`。安装包使用 ad-hoc 签名，未经过 Apple 公证。
