Atte 0.14.1 · macOS Apple Silicon

## 本版定位

0.14.1 是注意力中心版本的修复版，保留 0.14.0 的功能裁剪、设置页收敛、工作区 v5 迁移和 OMP Hook 修复。

## 修复

- 修复 0.13.x 后端切换或维护中断后升级到 0.14 的旧 Herdr binding：同一 Atte 安装会安全重绑到新控制代次；仍有现场引用的旧目标保留现场证据并冻结为只读历史，新目标可以正常开始。不同 Atte 安装的工作区会明确阻止接管，不再静默打开后所有操作失败。
- 收紧迁移确认的人机边界：受管 Agent 不能通过 `goal complete`、`goal drop` 或 `goal takeover` 清除 `migration-confirmation`。旧实验目标必须由人在桌面可信界面批准、拒绝或明确结束。
- 修复回执提醒投递 ID 冲突：提醒 ID 现在按 `goalId + attemptId + turnId` 隔离。Claude Code、Qoder 在并行目标或重启后出现相同 `turn-1` 时，不会再把第二个目标的提醒误判为原投递。
- 继续保留 0.14.0 的 OMP Hook 修复：受管 extension revision 3 在子进程提前退出时忽略 stdin `EPIPE`，有界排空输入并保持 fail-open；旧的托管 `crewvane.js` 会安全收敛，用户文件和符号链接不被覆盖。

## 升级注意

- 升级前关闭旧的 Atte 受管会话。首次打开工作区仍会校验 `state.v4.backup.json` 后再迁移到 v5。
- 如果 0.13.x 曾在后端切换中断后留下旧 Herdr 现场，0.14.1 会把这些现场标为只读历史；请在 Herdr 原终端核对后，按需要重新创建目标。
- 已运行的 OMP 进程可能继续持有旧 extension 代码；升级后请重启相应 OMP 会话。
- 回滚使用升级前备份，不要用旧版直接打开 v5 快照。

## 兼容性

保留 v2、v3 的既有迁移路径。已退役命令在读取或写入工作区前返回 `feature_removed`，历史记录仍可读取。`atte hook ingest` 的失败保持 fail-open，退出码为 0。

## 安装

仅支持 Apple Silicon Mac（arm64）。安装 DMG 或 ZIP 后启动应用即可；CLI 会随应用重新安装。
