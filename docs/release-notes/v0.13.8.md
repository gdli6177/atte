Atte 0.13.8 · macOS Apple Silicon

## 本版更新

- 负责人现场崩溃后可以自愈：`owner launch` 和“恢复并进入现场”会先核实旧现场进程确实已退出，再退役旧 attempt、建立新现场。旧 attempt 保留在 `attemptHistory` 并标为 `superseded`，不再需要人点按钮或手改 `state.json`。
- 启动后立即退出会被记作 `launch_failed`，本次现场自动清理，可直接重试；提示会说明可能是 Agent CLI 崩溃（例如 EPIPE）。这解决“已有现场”和“现场不可投递”互相卡住的问题。
- 巡检 stale 改为以负责人自己的最后一次写回为基准。管家写回进展、核对说明不会再推迟巡检，避免“写回—巡检”自激循环。
- 已有未答卡片时，巡检不再重复升级同一件事；卡片会保留到问题真正恢复或由人处理。
- 协调收件箱按 `(目标, requestId, 类型)` 幂等：同一请求重复投递只保留一条，已合并的记录不会继续增长。
- `unconfirmed` 投递 30 分钟后自动转为 `expired` 终态，不再长期挂在告警里；未确认与未送达保持区分，也不自动重发。
- 新增 `atte doctor [--json]`：版本、会话后端、状态库大小、收件箱排队/未确认/失败/过期数量、不可达现场和最近问题。受管管家也可以调用。
- 新增 `atte delivery REQUEST_ID [--json]`：查询一次协调投递的最终状态。
- 管家的 `atte status --json` 现在返回当前案卷摘要（状态、下一步、负责人、注意力、现场与可达性），与投递提示一致。

## 已知限制

- omp 自身的未捕获 EPIPE 是 Agent CLI 内部错误，Atte 不能替它处理；本版保证该退出被快速识别、记为启动失败并自动清理现场，恢复不再死锁。
- 跨后端且没有交接记录的现场仍按原规则拒绝自动退役，避免误判仍在工作的负责人。

## 兼容性

保持 0.13.7 的工作区格式；新增字段为可选，旧状态可直接读取。

## 安装

仅支持 Apple Silicon Mac（arm64）。替换 Atte.app 即可；不需要重装 CLI。
