Atte 0.13.5 · macOS Apple Silicon

## 本版更新

- 修复 Orca 模式“回到现场”后窗口仍在别的应用后面、或停在另一个桌面的问题。0.13.4 只在源码里加了激活逻辑却没有打进安装包，本版补上并用 AppKit `NSRunningApplication.activate(AllWindows)` 激活：置顶窗口并切到 Orca 所在桌面，无需自动化或辅助功能授权；失败时回落到 `open -a`。
- 修复负责人在独立 CLI 中写回 `progress`、`decide`、`review` 等结果后，管家要等到巡检（10 秒轮询或 30 分钟无进展检查）才行动的问题。桌面现在观察状态变化，把负责人这次写回作为一份独立案卷立即排入管家收件箱并尝试送达。
- 该通知不伪造目标派发状态：写回本身已经发生，即使管家暂时不可达，也只保留为队列告警并稍后重试，不会把目标标成“联系管家失败”或让你去处理一次并非故障的情况。
- 普通进展仍不进入注意力面板：只有需要你决定、验收、到期跟进或介入的事项才会出现目标仍在进行中，不会被自动当成完成。
- 待验收仍以 `atte goal review` 为准：只写 `progress` 不会凭空变成待验收，需要你验收必须提交带真实检查的交付。
- 观察器在应用启动时先记录既有历史，重启不会把旧进展重放成新通知；同一目标的连续写回按既有收件箱规则合并为最新一条。
- 新增 `pnpm test:semantic`：真实打包应用、真实 Herdr 与真实交互式 CLI 验证“负责人写回 → 管家立即收到第二份案卷 → 不产生注意力项”。

- 修复切换 Herdr ↔ Orca 后，存量目标的“恢复并进入现场”点了没有反应的问题。旧现场属于另一个后端时，适配器无法核实它：有交接记录则退役旧引用，并在当前后端重新创建咨询用负责人；没有交接记录时明确提示先完成交接，不再静默失败。
- 恢复现在会把切后端前的现场记入历史，目标和消息不受影响。

## 兼容性

保持 0.13.4 的工作区格式与协议；只新增对既有状态变化的观察与一种协调收件项，不改变目标、消息、交付或现场数据。

## 安装

仅支持 Apple Silicon Mac（arm64）。替换 Atte.app 即可；不需要重装 CLI。
